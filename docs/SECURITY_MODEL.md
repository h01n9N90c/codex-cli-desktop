# Mô hình Bảo vệ 4 Lớp, Ranh giới Thực tế & Cách ly Phân tích tĩnh cho Codex Agent

> **Tác giả:** Lê Hoàng Ngọc Tươi | **Dự án:** Codex Dual-Lane & Security Kit (Apache License 2.0)

Tài liệu này giải thích các rủi ro thực tế khi chạy AI coding agent trên Windows, macOS, Linux và WSL (đặc biệt khi dùng API bên thứ 3 hoặc làm dự án SAST/phân tích nhị phân), cách bộ kit xây dựng phòng thủ 4 lớp, **ranh giới trung thực giữa điều bộ kit đảm bảo và giới hạn của hệ điều hành / Codex runtime**, cũng như quy trình khôi phục an toàn.

## 2. Bốn lớp phòng thủ nhiều tầng (Defense-in-Depth)

### Lớp 1: Khóa Sandbox phạm vi Thư mục Dự án, 3 Chế độ Quyền Codex CLI, Toàn quyền File CRUD & Cách ly Mạng
* **Cưỡng chế ở cấp Hệ điều hành kèm Đầy đủ Tính năng Bản Gốc trong Thư mục Dự án (Hard OS Boundary + Native Codex Parity):** Ở chế độ mặc định **`Xin yêu cầu` (`Ask`)** (`sandbox_mode = "workspace-write"` + `approval_policy = "on-request"`), agent được trao **đầy đủ năng lực bản Codex CLI gốc** bên trong thư mục dự án được tin cậy (`cwd`) và thư mục tạm (`%TEMP%` / `/tmp`): nắm bắt toàn bộ cây thư mục (`rg --files`, `git status`, `Get-ChildItem`, `find`), **tự do đọc, ghi, tạo mới, chỉnh sửa, đổi tên, xóa file**, build/test/debug và dùng trọn vẹn các tính năng gốc (`memories`, `goals`, `image_generation`, `api_key_model_discovery`, MCP, skills, `[features]` người dùng). Thuật toán, tài liệu hoặc mã nguồn bên ngoài thư mục dự án chỉ được **tham khảo ở chế độ chỉ-đọc (read-only)**; toàn bộ ổ hệ thống bên ngoài workspace (`C:\`, `/etc`, ...) và các thư mục nhạy cảm như `.git/` hooks, `.codex/`, `.agents/` được bảo vệ bởi tầng sandbox của Codex (`[windows] sandbox = "elevated"` trên Windows; Seatbelt/Landlock trên macOS/Linux).
* **3 Chế độ Quyền Codex CLI Luồng 2 (v1.4 — chọn qua `codex-manage` `[7]` hoặc `-CliMode` / `--cli-mode`):**
  1. **`Xin yêu cầu` (`Ask` / `ask` — Mặc định):** `approval_policy = "on-request"` + `sandbox_mode = "workspace-write"` — gọn trong thư mục dự án, chỉ tham khảo thuật toán bên ngoài ở chế độ chỉ-đọc, giữ đầy đủ tính năng bản Codex chính, hỏi duyệt trước lệnh nhạy cảm hoặc ngoài sandbox.
  2. **`Thuộc cấu hình config.toml` (`Config` / `config`):** Tôn trọng nguyên vẹn `approval_policy` (`"on-request"`, `"never"`, `"on-failure"`, bảng `granular`) và `sandbox_mode` (`"read-only"`, `"workspace-write"`, `"danger-full-access"`) mà người dùng tự đặt trong `~/.codex-official/config.toml` (không bị ghi đè). *(Lưu ý: `approval_policy = "untrusted"` không còn được hỗ trợ trên `codex-cli 0.171.0-alpha.13`.)*
  3. **`Toàn quyền` (`FullAccess` / `full-access` — DANGER):** `approval_policy = "never"` + `sandbox_mode = "danger-full-access"` — bắt buộc hiển thị **khung cảnh báo nguy hiểm màu đỏ/vàng như bản Codex thật** và yêu cầu xác nhận tường minh (`TOAN QUYEN` / `I UNDERSTAND` khi tương tác, hoặc `-ConfirmFullAccess` / `--confirm-full-access` khi không tương tác; `-Force`/`--force` một mình không thể vượt qua), **từ chối fail-closed (`exit 1`, `0` thay đổi)** nếu không xác nhận. Chỉ dùng khi đã tạo checkpoint Git hoặc cô lập trong worktree riêng.
* **Ngắt mạng đầu ra mặc định trong Shell Sandbox (`[sandbox_workspace_write] network_access = false`):** Chặn tiến trình con trong shell sandbox mở kết nối mạng ra ngoài (chống exfiltration dữ liệu và tải payload), trong khi tiến trình Codex ở ngoài vẫn gọi API LLM bình thường.
* **Phân vùng ghi giữa 2 Agent — Ranh giới Mềm vs. Ranh giới Cứng (`-UseGitWorktree` / `--use-git-worktree`):**
  * **Chung 1 thư mục dự án (mặc định):** Ranh giới mềm (Prompt Boundary) qua `AGENTS.md` và `DUAL_LANE_BRIDGE.md`.
  * **Tách Git Worktree riêng (`-UseGitWorktree` / `--use-git-worktree`):** Tạo worktree riêng `<repo>-lane2` cho Luồng 2 để sandbox `workspace-write` khóa cứng từng luồng vào cây thư mục độc lập.

### Lớp 2: Quản lý Secret (`env_key` & `keyring`), Khai thác Chỉ-đọc (Bảo toàn `trust_level`), Cảnh báo Opt-In Auth-Share, Linh hoạt Login + API Key cho CLI, Lọc biến môi trường & Khóa Quyền Tệp (NTFS ACL / POSIX)
* **Không lưu plaintext API key trong `config.toml`, Kế thừa Chỉ-đọc `[projects.*]` theo đúng `trust_level`, Xác nhận Tin cậy Tường minh (`-TrustRepoPath` / `--trust-repo-path`) & Hỗ trợ Linh hoạt cả Login lẫn API Key cho CLI (v1.4):** Bạn có thể giữ **Luồng 1 (`~/.codex`, Codex Desktop)** cho **Tài khoản chính (`acc chính`)** mà không sửa 1 byte nào trong `~/.codex/config.toml` hay `~/.codex/auth.json`, trong khi bộ cài **đọc chỉ-đọc (`read-only`)** `~/.codex/config.toml` để kế thừa `[projects."..."]` sang **Luồng 2 (`~/.codex-official`, Codex CLI)** với **ranh giới tin cậy nghiêm ngặt**: chỉ ghi `trust_level = "trusted"` cho dự án thật sự là `"trusted"`, bảo toàn nguyên vẹn `trust_level = "untrusted"` (không bao giờ tự nâng cấp thành `"trusted"`), không nâng cấp mục thiếu `trust_level`, và **không tự nâng `-RepoPath` / `--repo-path` lên `"trusted"`** trừ khi bạn chủ động truyền cờ `-TrustRepoPath` / `--trust-repo-path`. Đồng thời bạn có thể cấu hình Luồng 2 CLI dùng **cả Đăng nhập OAuth (`codex login`) lẫn API Key / cổng Gateway** chỉ với 1 cờ `-ConfigureCliGateway` + `-CliApiKeyEnv` (Windows) hoặc `--configure-cli-gateway` + `--cli-api-key-env` (Unix), hay tùy chọn luồng qua `-GatewayTargetLane Lane2|Lane1|Both` / `--gateway-target-lane lane2|lane1|both`. Bộ kit chỉ ghi thuộc tính **`env_key = "<TEN_BIEN_MOI_TRUONG>"`** (kết hợp nhập ẩn qua `-PromptGatewayApiKey` bằng `Read-Host -AsSecureString`), **tuyệt đối không ghi plaintext key hay `experimental_bearer_token` vào `config.toml` hoặc các tệp `.backup-*`**.
* **Cảnh báo cờ tùy chọn `-ShareAuthToLane2` / `--share-auth-to-lane2` (Strictly Opt-In — tắt mặc định):** Cờ này tắt mặc định; chỉ khi người dùng chủ động bật mới sao chép nguyên tử `~/.codex/auth.json` sang `~/.codex-official/auth.json` với khóa ACL 2 bước / `chmod 600` và theo dõi rollback (giữ `~/.codex/auth.json` nguyên vẹn 100%). Vì thao tác này **tạo bản sao thứ 2 của `auth.json` (OAuth token)** tại Luồng 2, **hãy tránh hoặc hết sức thận trọng khi Luồng 2 được cấu hình với cổng API bên thứ 3** (script sẽ tự phát cảnh báo `[WARN]` mỗi khi cờ này được bật, và cảnh báo nổi bật hơn nếu kết hợp cờ cổng API bên thứ 3).
* **Khuyến nghị vệ sinh mật khẩu/token mức cao nhất (`keyring` + `env_key`):**
  * Để tránh lưu OAuth token dạng tệp văn bản trong `auth.json`, hãy cân nhắc bật trong `config.toml` (khi phiên bản Codex của bạn hỗ trợ):
    ```toml
    cli_auth_credentials_store = "keyring"
    ```
  * Khi kết hợp `cli_auth_credentials_store = "keyring"` cho tài khoản đăng nhập và `env_key` cho API key / cổng API, ngay cả khi DACL tệp `config.toml` bị reset sau lần ghi đè atomic của Codex, tệp vẫn không chứa secret dạng rõ.
* **Lọc biến môi trường sang shell con (`[shell_environment_policy]`):**
  ```toml
  [shell_environment_policy]
  exclude = ["*KEY*", "*SECRET*", "*TOKEN*", "*PASSWORD*", "*CREDENTIAL*"]
  ```
  Khi agent mở PowerShell/CMD/Bash chạy lệnh build hoặc test, các biến môi trường khớp mẫu nhạy cảm sẽ bị lọc bỏ khỏi tiến trình shell con (trong khi tiến trình cha Codex Rust vẫn đọc được biến `env_key` từ môi trường hệ thống để gọi API LLM bình thường).
* **Khóa quyền tệp ở tầng hệ thống tệp:**
  * **Trên macOS / Linux / WSL:** Dùng `umask 077`, `chmod 700` cho thư mục nhạy cảm và `chmod 600` cho `config.toml`, `auth.json`, bản sao lưu và các tệp JSONL đồng bộ.
  * **Trên Windows (Quy trình `icacls.exe` 2 bước):**
    Vì thư mục `~/.codex` có thể mang quyền kế thừa `CodexSandboxUsers:(OI)(CI)(RX)`, việc chỉ chạy `icacls <file> /remove:g "CodexSandboxUsers"` sẽ **không xóa được ACE kế thừa**. Do đó `Protect-SensitiveFileAcl` trong `setup-dual-lane.ps1` chạy **2 lệnh tuần tự**:
    ```cmd
    icacls "<file>" /inheritance:d
    icacls "<file>" /remove:g "CodexSandboxUsers"
    ```
    1. **Bước 1 (`/inheritance:d`):** Tắt kế thừa quyền từ thư mục cha và chuyển các ACE kế thừa thành ACE tường minh (giữ nguyên quyền của chủ sở hữu / `SYSTEM` / `Administrators`, không bao giờ tự khóa quyền chính bạn).
    2. **Bước 2 (`/remove:g "CodexSandboxUsers"`):** Chỉ chạy khi nhóm `CodexSandboxUsers` tồn tại trên máy, gỡ hẳn **Allow ACE** đọc của nhóm sandbox mà không chạm tới bất kỳ Deny ACE bảo vệ nào. Nếu máy mới chưa có nhóm `CodexSandboxUsers`, bước 2 tự động bỏ qua an toàn mà không làm hỏng cài đặt. Ngoài ra `doctor.ps1` chỉ kiểm tra tham khảo (read-only) sự tồn tại của `.sandbox\deny_read_acl_state.json` (không sửa hay in nội dung).
    * *Lưu ý quan trọng về atomic replace:* Như đã nêu ở Mục 1, các lệnh như `codex features enable ...` hoặc chỉnh Settings trong Codex Desktop ghi lại `config.toml` theo kiểu atomic replace nên Windows sẽ cấp lại DACL kế thừa từ thư mục cha. Hãy chạy `.\scripts\doctor.ps1` để kiểm tra chỉ số `kernel_acl` và chạy lại bước khóa ACL sau khi thay đổi cấu hình trong Codex.

### Lớp 3: Tường lửa chặn lệnh nguy hiểm & Cách ly phân tích tĩnh (`rules/default.rules`)
Codex nạp tệp Starlark `rules/default.rules` vào tầng Rust execpolicy **trước khi chạy lệnh trực tiếp** (có hiệu lực ngay cả khi bật `approval_policy = "never"`). Mọi quy tắc đều được chú thích rõ lý do ngay trong `templates/default.rules` kèm các biến thể `.exe`/`.com`/chữ thường:
* **Cấm tuyệt đối (`decision = "forbidden"`):**
  1. **Chống hành vi phá hệ thống / ransomware:** `vssadmin`, `bcdedit`, `wbadmin`, `diskpart`, `format` *(kèm `.exe`/`.com`)*.
  2. **Chống cài cắm persistence & sửa Registry:** `schtasks`, `sc`, `reg add`, `reg delete`, `reg import` *(kèm `.exe`)*.
  3. **Chống hạ cấp NTFS ACL, chiếm quyền sở hữu & phá cấu hình mạng:** `icacls`, `takeown`, `net`, `net1`, `netsh` *(kèm `.exe`)*.
  4. **Chống phá lịch sử Git từ xa:** `git push --force`, `git push -f` *(kèm `git.exe`)*.
  5. **Cách ly phân tích tĩnh (`Static-Analysis-Only Isolation`):**
     * *Trình thông dịch mẫu corpus:* `php`, `ruby`, `perl` *(kèm `.exe`)*.
     * *Windows Script Host, LOLBins & thực thi động:* `cscript`, `wscript`, `mshta`, `rundll32`, `regsvr32`, `certutil`, `bitsadmin`, `msiexec`, `wmic`, `Start-Process`/`start-process`/`saps`, `Invoke-Expression`/`invoke-expression`/`iex`/`IEX`.
* **Bắt buộc người dùng xác nhận (`decision = "prompt"`):**
  * `git push`, `git reset --hard`, `git clean` *(kèm `git.exe`)*.
* *Lưu ý ranh giới kỹ thuật:* `prefix_rule` kiểm khớp chính xác theo tiền tố lệnh trực tiếp (`argv[0]`), không phân tích hết mọi chuỗi lồng trong `powershell -Command "..."` hay `bash -c "..."`. Vì vậy luôn duy trì đủ cả 4 lớp phòng thủ cùng Windows Defender / AV của máy.

### Lớp 4: Chỉ thị Chống Prompt Injection, Phân tích tĩnh bắt buộc, Đầy đủ Tính năng Gốc Gọn trong Dự án & Tham khảo Bên Ngoài Chỉ-Đọc (`AGENTS.md` toàn cục)
* Ép mô hình coi mọi nội dung tệp, chuỗi trong file nhị phân, comment, log là **dữ liệu không tin cậy**, không bao giờ làm theo mệnh lệnh ẩn trong dữ liệu.
* **Cách ly phân tích tĩnh (`Static-Analysis-Only Isolation`):** Cấm tuyệt đối thực thi/kích nổ bất kỳ tệp mẫu mã độc nhị phân (`.exe`, `.dll`, `.elf`, `.so`, `.bin`) hay tệp mẫu lỗ hổng bên thứ 3 (`.php`, `.vbs`, `.hta`, payload `.js`/`.py`); chỉ được đọc tĩnh và chạy compiler/parser/disassembler/unit test đáng tin cậy của chính dự án — tuyệt đối không cản trở lập trình, refactor, build hay test bình thường.
* **Đầy đủ Tính năng Bản Codex CLI Gọn trong Thư mục Dự án & Tham khảo Bên Ngoài Chỉ-Đọc (`Rule 6`):** Khẳng định rõ trong phạm vi thư mục dự án (hoặc worktree Luồng 2), agent có đầy đủ năng lực kỹ thuật của bản Codex chính thức (duyệt toàn bộ cây thư mục `rg --files`, `git status`, `Get-ChildItem`, `find`, tự do đọc/tạo/sửa/di chuyển/xóa file dự án, build/test/debug, dùng MCP/skills/memories/goals/native `[features]`), giữ mọi thao tác ghi gọn gàng trong thư mục dự án và **chỉ tham khảo thuật toán, tài liệu, thư viện bên ngoài ở chế độ chỉ-đọc (read-only)**; đồng thời tóm tắt rõ 3 chế độ quyền CLI (`Xin yêu cầu` / `Thuộc cấu hình config.toml` / `Toàn quyền`).
* Cấm tự ý đọc/in `~/.codex/config.toml`, `~/.codex/auth.json`, `~/.codex-official/`, `.rollback/`, `.ssh/`, hồ sơ trình duyệt, `.env` hoặc biến môi trường chứa secret.

## 3. Nguyên tắc "Khiên Git" & Khôi phục Trạng thái An toàn (Safe Rollback)

### 3.1. Tạo Checkpoint Git trước mỗi đợt chạy dài
Trước khi giao cho agent chạy nhiều pha tự động:
```powershell
git add -A
git commit -m "checkpoint: before agent run"
git push
```
Nếu sau khi chạy cần kiểm tra hoặc hoàn tác thay đổi mã nguồn:
```powershell
git diff --stat              # Xem nhanh danh sách tệp bị sửa
git reset --hard HEAD        # Quay về trạng thái checkpoint sạch
```

### 3.2. Gỡ Sandbox 2 Không Mất Lịch Sử Chat (`RemoveSandbox2` / `remove-sandbox2`) & Khôi phục Cấu hình Bộ Kit An toàn (SHA-256 Verified Rollback)
* **Cách khuyến nghị khi muốn xóa Sandbox 2 (`~/.codex-official` — Codex CLI) mà bảo toàn 100% lịch sử chat về GPT 1 (`~/.codex`) (v1.4.0):**
  * **Windows:**
    ```powershell
    .\scripts\codex-manager.ps1 -Action RemoveSandbox2 -DryRun
    .\scripts\codex-manager.ps1 -Action RemoveSandbox2
    ```
  * **macOS / Linux / WSL:**
    ```bash
    ./scripts/codex-manager.sh --action remove-sandbox2 --dry-run
    ./scripts/codex-manager.sh --action remove-sandbox2
    ```
  * **Cơ chế Fail-Closed bảo toàn 100% lịch sử chat:** Trước khi xóa bất cứ thứ gì, `codex-manager.*` **bắt buộc** chạy `scripts/sync-sessions.py --source <Lane2> --target <Lane1> --rescue-shared-files --backup-target` để sao lưu SQLite GPT 1, đồng bộ ngược toàn bộ `session_index.jsonl`, `state_*.sqlite` (threads/Pinned), `goals_*.sqlite`, và sao chép không ghi đè mọi tệp rollout/memory cục bộ (từ chối symlink fail-closed) về **GPT 1 (`~/.codex`)**. Nếu bước cứu hộ này gặp lỗi, script dừng ngay (fail-closed) và **không xóa Sandbox 2**. Chỉ khi cứu hộ thành công, script mới gọi `restore-original.* -RemoveLane2Home` / `--remove-lane2-home` để tháo sạch Junction/symlink trước rồi mới xóa `~/.codex-official` và xác minh lịch sử GPT 1 còn nguyên vẹn 100%.
* **Khôi phục thuần theo Snapshot SHA-256 (`restore-original.*`):**
  * **Windows:** Luôn chạy `-DryRun` trước để kiểm tra mã băm SHA-256 và danh sách thao tác, sau đó chạy khôi phục chính thức:
    ```powershell
    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore-original.ps1 -DryRun
    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore-original.ps1
    # Nếu muốn dọn luôn thư mục ~/.codex-official sau khi đã kiểm chứng tháo 6 Junction:
    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore-original.ps1 -RemoveLane2Home
    ```
  * **macOS / Linux / WSL:**
    ```bash
    ./scripts/restore-original.sh --dry-run
    ./scripts/restore-original.sh
    # Hoặc dọn luôn ~/.codex-official sau khi đã gỡ an toàn 6 symlink:
    ./scripts/restore-original.sh --remove-lane2-home
    ```
* **Bảo vệ chống Path Traversal, Phục hồi Cài đặt Bị Ngắt, Bảo tồn Link Có Trước & Bảo vệ Dữ liệu Luồng 1 (v1.3.1–v1.4.0):** Vì bộ cài ghi nhật ký rollback tăng dần sau từng thao tác (`Completed: false` / `# status=in-progress` cho tới khi hoàn tất), nếu cài đặt bị ngắt giữa chừng bạn chỉ cần chạy `restore-original.ps1` / `restore-original.sh` để hoàn nguyên sạch toàn bộ tệp, 4 launcher (kể cả `codex-manage`) và Junction/symlink bán phần mà không chạm tới các launcher cũ chưa bị sửa. Từ v1.3.1, rollback kiểm tra quyền sở hữu link (`SharedLinkRecords` / `L` rows): **các Junction/symlink do người dùng tự tạo trước đó được bảo toàn nguyên vẹn**, không bị tháo nhầm; thư mục được khôi phục chính xác từ đường dẫn ghi trong manifest (không đoán mò wildcard); và bước kiểm tra preflight kiểm tra đầy đủ mọi tệp/thư mục sao lưu — nếu thiếu backup bắt buộc, script sẽ **lập tức dừng với mã thoát 1 fail-closed trước khi gỡ bất kỳ Junction nào hay thay đổi đĩa**. Script khôi phục luôn kiểm tra mọi đường dẫn trong manifest nằm trong phạm vi thư mục Codex được phép, xác minh mã băm SHA-256 trước khi ghi đè, hỗ trợ chạy lại nhiều lần (idempotent), và **luôn tháo 6 NTFS Junction / symlink trước** khi thực hiện bất kỳ thao tác xóa thư mục nào để dữ liệu thật trong `~/.codex` không bao giờ bị ảnh hưởng.

## 4. Phân biệt rủi ro thật vs. "hoảng loạn nhầm" khi dùng cổng API bên thứ 3

| Tình huống | Bản chất kỹ thuật | Cách xử lý chuẩn |
| :--- | :--- | :--- |
| Thấy AI tự nhiên nhả ra 1 cụm chữ lạ / quảng cáo SEO trong khung chat | Có thể là **Glitch Token / Training Data Artifact** hoặc chuỗi chèn từ cổng relay bên thứ 3 — **không tự biến thành mã độc/ransomware trên Windows** nếu agent không thực thi lệnh độc hại | 1. Kiểm tra diff mã nguồn (`git diff`, `git log -S`).<br>2. Kiểm tra Windows Defender (`Get-MpComputerStatus`) & Startup Registry.<br>3. Nếu muốn ngừng dùng gateway, chạy `restore-original.ps1` (hoặc khôi phục `~/.codex/config.backup.toml`) và xóa biến môi trường key. |
| Lo ngại cổng relay lưu log mã nguồn | **Rủi ro có thật về quyền riêng tư:** Cổng trung gian bên thứ 3 có thể ghi log prompt/code gửi qua máy chủ của họ | **Tách việc theo độ nhạy cảm:**<br>- Code mã nguồn mở / thuật toán chung $\rightarrow$ có thể chạy Luồng 1.<br>- Code chứa bí mật, tài sản độc quyền, thông tin nhạy cảm $\rightarrow$ chạy **Luồng 2 (Tài khoản OpenAI chính chủ)**, không bao giờ đưa `.env` hay secret thật vào repo. |
| Windows Defender báo cảnh báo mã độc (vd `Backdoor:PHP/...`) trên tệp `~/.codex/sessions/.../rollout-*.jsonl` khi làm dự án SAST/an ninh | **Cảnh báo nhầm (False Positive) phổ biến trên log hội thoại:** Khi agent đọc tĩnh tệp test chứa chuỗi giả lập webshell/payload, Codex ghi nguyên văn text đó vào log `.jsonl`, khiến AV bắt chữ ký tĩnh — **không phải agent chạy mã độc** | 1. Kiểm tra `Get-MpThreatDetection` để xác nhận `Resources` chỉ là tệp text `.jsonl`, không phải `.exe`/`.php` đang chạy.<br>2. Xác nhận `network_access = false`, `default.rules` chặn LOLBins/interpreter và `AGENTS.md` bật `Static-Analysis-Only`.<br>3. Không bấm Quarantine lên tệp `.jsonl` đang ghi dở; chuyển sang `/new` trước khi dọn log cũ nếu cần. |
| Muốn quay về cấu hình Codex gốc ngay lập tức | Mọi tệp bị chỉnh sửa đều có bản sao lưu `.backup-yyyyMMdd-HHmmss` tracked trong `.rollback/latest.json` (và riêng `-ConfigureGateway` lưu thêm `~/.codex/config.backup.toml` bản sạch đầu tiên) | Chạy `.\scripts\restore-original.ps1 -DryRun` rồi `.\scripts\restore-original.ps1` (hoặc `./scripts/restore-original.sh` trên Unix) và khởi động lại Codex Desktop. |
